# 实时转写 AI 校对

桌面录音的每个定稿片段，在发布 `transcript-update` 前调用盒子上的本地 Qwen3-4B。模型只修正明确错字和标点；通过硬校验的文本直接显示，不增加建议按钮或审核页面。部分预览、导入、重新转写和会后批量不使用这条链路。

## 模型与开关

- 模型固定为 `qwen3-4b`，复用 `RK_SUMMARY_ENDPOINT`：`http://127.0.0.1:8040/v1/chat/completions`。
- 不安装 Ollama，也不新增 `/v1/asr/correct-text` Python 接口。
- 环境变量 `MEETINGBOX_ASR_REWRITE=0` 可关闭；默认开启。其它非法值保守关闭。
- 每句请求最多等待 1.5 秒（包含服务端排队和响应读取）。超时或服务不可用后，本场会议停止校对，下次录音重新尝试。
- ASR 已有下一片段排队时，优先处理转写，本场会议停止校对。不会后台重试或向共享模型连续提交过期请求。
- 上下文来自前两段原始定稿文字，合计最多 400 字；当前段超过 512 字直接保留原文。

## 校验与原文

数字表达（含单位、百分比、日期、顺序和重复次数）、否定词和发言人标签受硬检查保护。另限制 Unicode 长度及去除标点后的编辑比例。非法或歧义 JSON、截断响应、校验失败一律保留原文。

每个会议文件夹增加 `transcript_corrections.jsonl`：

1. revision 0：完整原文、录音 session、sequence_id、原始起止时间及定稿时间，先写入并同步。
2. revision 1：选定文字、校对状态、拒绝原因、模型与提示词版本、耗时，再写入并同步。

两个 revision 通过 `recording_session:sequence_id:0` 关联。只有档案保存成功的修正才会替换显示；档案不可写或会议目录缺失时，保留原文。这里的原文是现有 provider 返回且已经经过热词处理的文字。

`transcripts.json` 与最终 SQLite 正文保存用户所见文字，格式不变。原文档案独立保存，后续手工修改正文不会覆盖档案。档案属于会议目录中的敏感数据，应随会议文件管理，不提交仓库。

## 能力边界

这是文字校对，不重听音频。专有名词、方言或无法从文字判断的识别错误可能保持原样。硬检查不能证明姓名、承诺和所有语义不变，模型采用保守提示词。未改动是正常结果，不以改动数量评估效果。

校对与纪要共享 RK1828 的串行服务；繁忙时及时保留原文。带否定词的句子会额外保护内部标点的位置，避免“不同意”与“不，同意”之类含义变化，因此部分正常补标点也会被保守拒绝。

1.5 秒只限定模型请求；原文和决策同步落盘的耗时另外计入端到端延迟。磁盘异常缓慢时仍可能拖慢定稿，应结合实际 ASR 队列和总处理耗时验收。

## 本次验证结果

已在盒子 ARM64 环境的独立源码目录通过：

- 生产模块集成测试 12 项：通过修正、原文留档、超时和 503 熔断、非法/超大/截断响应、ASR 积压、上下文和会话隔离、原文/决策写盘失败、保存句柄移交后的尾段 flush。
- 纯解析与校验测试 14 项：JSON、数字/单位/日期/顺序、否定表达和位置、发言人标签、长度和内容编辑预算。
- `cargo check --offline --locked -p meetily --lib` 通过。
- 最终提示词的 4 条合成文本经真实 Qwen3-4B 服务测试，单段耗时 387–478 ms：`会议记要` 修正为 `会议纪要`，`方按` 修正为 `方案`，长句补逗号；带否定词样本因内部标点变化被拒绝并保留原文。原文与最终决策均已核对。

这些样本不能代表持续会议负载或一般纠错准确率。尚未替换已安装桌面包，实际桌面录音、停止尾段、音频保存开/关、SQLite 与显示一致性及并发纪要负载尚需在运行版本中验收。本机和现有盒子工具链均无 `rustfmt`，未执行该检查。

## 复现验证

```sh
cargo test --manifest-path tests/transcript-correction/Cargo.toml
cargo test --manifest-path tests/transcript-correction-validation/Cargo.toml
cargo check --locked -p meetily --lib
```

在盒子上执行合成文字 smoke，不读取真实会议内容：

```sh
cargo test --manifest-path tests/transcript-correction/Cargo.toml box_synthetic_smoke -- --ignored --nocapture
```

实际桌面验证还应覆盖：连续讲话时队列不增长、录音停止前最后一段、音频自动保存开/关、分钟摘要并发下的超时回退、连续两场会议的上下文和熔断隔离。故障路径使用 mock，不需要停止已有模型服务。
